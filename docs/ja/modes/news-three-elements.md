# 新聞三要素模式（Agent プリセット）

[中文](../../zh/modes/news-three-elements.md) | [English](../../en/modes/news-three-elements.md) | 日本語  | [偽中国語](../../pcn/modes/news-three-elements.md)

> 極簡模式から派生した**読取専用**の創作プリセット：実在のニュース形式でロシア風速報を創作する。ここでの「新聞三要素」は**必ず揃わなければならない三人の主人公**——バランニコフ、ユディンツェフ、ブヤノフ——であり、セッション初期化時に技能パッケージ全体をオンライン取得する。

## 基本情報

| 項目 | 値 |
|------|-----|
| モード id | `news-three-elements` |
| 配布方式 | **独立パッケージ** `dsh-preset-news-three-elements`（`packages/dsh-preset-news-three-elements.nix`）。モジュールが `$out/share/dsh-agent-presets` を roster の追加プリセットルートとして登録 |
| 有効化オプション | `nixkits.dsh.presets.newsThreeElements = true` |
| パッケージ上書き（任意） | `nixkits.dsh.presets.newsThreeElementsPackage`（既定 `pkgs.dsh-preset-news-three-elements`） |
| 派生元 | 極簡模式（dsh 同梱の `minimal` プリセット） |
| 技能依存 | リポジトリ `skills/news-three-elements/`（セッション起動時にオンライン取得、同梱スナップショットをフォールバック） |

## 動作

**タス通信、Meduza、iStories 総合電** —— 本リポジトリ engineering desk の通報によれば、本モードが行うことはただ一つ：技能に従って速報を創作することである。その他の挙動は以下の通り：

- **読取専用**：閲覧系ツールのみをマウントする（`read`、`read_image`、`glob`、`grep`、`web_search`、`web_fetch`、`skill`、`ask_user_question`）；`write` / `edit` はツール表に載っているが、呼び出しは一律 `readonly-gate` が通信社の文体で拒否する（許可リスト外は既定拒否のため、将来追加されるツールも誤って通ることはない）。読み取りにも範囲があり、絶対パスは**ワークスペース・添付ディレクトリ・`/tmp`・自身の技能パッケージ**（取得キャッシュ + 同梱スナップショット）の配下だけ許可し、それ以外は拒否する（相対パスはファイルシステム側の解決に委ねる）。
- **三人が揃う**：本モードの「新聞三要素」は報道学の三要素ではなく、実在する三人のゲーム製作者——バランニコフ（『War Thunder』プロデューサー）、ユディンツェフ（Gaijin 創業者）、ブヤノフ（Battlestate 創業者）——である。速報の本文には必ず三人が現れ、一人でも欠ければ書き直し。利用者が素材を持ち込んだ共創でも同じで、素材は導火線、三人は固定装備である。
- **素材優先、接続できないときだけ断る**：三人の主人公・ロシア風ニュースの外殻・遊技機構のいずれかに触れるリクエスト（業界の噂、機構への不満、時事への追及、他人のネタ、一枚のスクリーンショット）は、すべて素材として扱う——まず検索で補い、三人に掛けて一篇に仕立てる。**「これは報道創作のリクエストではない」を理由に拒否してはならない。** 仮定の疑問（「ブヤノフがシステムに『淘汰済み』と判定されたら？」）は**既に起きたこと**として書き、反问も論証もしない。名指しでない人物（「某位制作人」「経済モデルを毎日いじっている奴」）は身分対応表で三人のいずれかに当てはめ、名前の補完を求めない。素材不足は事実の外殻だけ補えばよく、拒否の理由にはならない。
- **素材は導火線にすぎない——検索が無ければ発稿できない**（`news-material` プラグインの厳格なゲート）：利用者の素材は手掛かりにすぎず、本文はその回の検索から書き直す——**抽出 → 投射 → 張り替え**の三工程。利用者の原文から**連続 8 文字以上の漢字**を写してはならない（数えるのは漢字のみなので、ラテン文字の作品名は命中しない。「本稿取材」の一行は素材を意図的に引用するため除外）。ゲートは二段構え：書き出す前、人のメッセージを受理するステップに「取材鉄律」が同送され、納品時（`agent/turn-stopping`——ループが回合を閉じる前に読み直す停止境界）にその回合自身のログを読む——**`web_search` / `web_fetch` の呼び出しが一度も無い、または利用者の原文を写した**回合には「編集部退稿」を返し、同じ回合のもう一歩を走らせる。**退稿は回合ごとに一度**きりなので、無視するモデルも無限ループにはならない。素材の範囲は利用者のメッセージと、それがモデルに指し示したファイル（その回合の `read` 結果）。検索結果は素材に**含めない**——通信社の言い回しを再利用することこそ本モードの目的である。
- **オンライン技能パッケージ**：セッション起動時にリポジトリ `skills/news-three-elements/` の全パッケージを取得する（5 ファイル、8 秒上限；失敗時は 0/30/120 秒で再試行、長時間セッションでは 6 時間ごとに再確認）。先にローカルの最新副本を登録する（キャッシュ優先、無ければ同梱スナップショット）。5 ファイルは**並列取得**し、**ETag による条件付きリクエスト**を送る——内容が変わっていなければ 304 が返るだけで書き直さない。技能パッケージは読取専用でマウントされ、速報はディスクに残らない。
- **開始時問答**：セッション初期化完了後に三択を提示する（クライアント側は自由入力も可）。選択は `agent.followup()` を通じて本セッション最初のユーザーメッセージになる。利用者が回答前に自分から話し始めた場合、問いは**自動的に取り下げられ**、その一文が開始の合図になる。自由入力の回答は一律拒否し「请点选上方选项」と促す——この規則が縛るのは開始時問答そのものだけで、着席後に出た質問は上の素材優先規則で処理する。
- **言語審査**：簡体中文以外のリクエストは一律拒否する（漢字なし / 仮名 / ハングルはプラグインがハード検出し、**判定対象は人の発言のみ**——harness が注入する承認通知や技能目録は数えない（英語のシステム一行で簡体中文の依頼を範囲外と誤判定してしまうため）、繁体中文には**保守的な繁体専用字の判定**を一つ加え、高信頼のときだけ命中させ、残りはモデルに委ねる）。拒否文は中国語の通信社文体で書かれ、その後**《好意で》同じ拒否文のローカライズ版を添える**——訳文が出るのは**言語審査が引き金になった場合に限られ**、かつ**相手が実際に使った言語そのもの**で書く（英語なら英語、日本語なら日本語、繁体中文なら繁体中文。第三の言語に置き換えない）。簡体中文の利用者に対する拒否には**訳文を付けない**——言語自体が正当なので、翻訳すべきものが無い。中国語学習の示唆は**毎回引き直す**。引かれるのは**人**である——3 名の制作者から 1 名を無作為に選び、ゲームは人に従う（ユディンツェフとバランニコフ → "War Thunder"、ブヤノフ → "Escape from Tarkov"）。これに「緑のフクロウ」ソフトを加えた 4 通りの等確率で、1 回の拒否につき必ず 1 つだけ。さらに**連続して同じものを引かない**（直前に引いた項目は次の抽選から外す）。「緑のフクロウ」は文脈が合えば「绿毛鸡」と略せる。
- **拒否の素材はその場で取る**：上の規則でなお接続できないリクエストだけが拒否の流れに入る。拒否のたび（言語審査の回も）まず Web を検索し、その日の実際の報道表現・公式の言い訳・機関の発表を材料にする。理由・文型・結びの反転を前回から使い回してはならない。機械的な反復は本モードで最も重い失態とみなされ、語り口は常に「至極真面目にデタラメを言う」底色で通す。

## コンポジション構造

| 行 | 出所 | 役割 |
|------|------|------|
| `persona`（`complete: true`） | dsh 内蔵 | 唯一のプロンプト源：読取専用の境界、三人の定義、素材優先の判定、開始時暗号表、素材の共同創作、拒否の話術 |
| `tool-fs` / `tool-fs-search` / `tool-web` / `tool-skill` / `tool-ask-user` | dsh 内蔵 | 読取専用サーフェス |
| `news-skill` / `news-opening` / `news-language` / `news-material` / `readonly-gate` | 本パッケージ `plugins/*.js` | オンライン取得、開始時問答、言語ゲート、取材ゲート（検索が無ければ発稿不可）、読取専用ガード |

パッケージ内プラグインは**相対行名**（`./plugins/*.js`）でマウントする——コンポジションの `baseUrl` はプリセットディレクトリ自身であり、プラグインは Node 組み込みモジュールのみに依存するため、ディレクトリごと store に置いても解決でき、node_modules は不要。

## インストール

```nix
{
  nixkits.dsh.presets = {
    newsThreeElements = true;
    # 任意：自前 / 上書きのプリセットパッケージに差し替える
    # newsThreeElementsPackage = pkgs.dsh-preset-news-three-elements;
  };
}
```

`nix flake check` 通過、`nixos apply` 完了後、セッションのモード選択器に直ちに「新聞三要素模式」が現れる。

## 注意

- **コピーも書込みもしない**：プリセットはパッケージの store パスから直接読む（`trust: system`）。`$DSH_HOME/.agent-presets` 配下に**その副本は存在しない**——更新すれば即座に新しくなり、再シードは不要。設定ルートはユーザールートより先に走査されるため、同名 id は本パッケージのものが優先される。
- **変更したい場合**：roster の `copy()`（または手動でのディレクトリ複製）で別 id のユーザープリセットとして保存し、その副本を編集する；同名ディレクトリをユーザールートへ直接置いても有効にならない。
- パッケージ内プラグイン `news-skill` は取得した技能パッケージを `$DSH_HOME/.cache/news-three-elements/` へ書き込む——これが唯一の書込み操作である。
