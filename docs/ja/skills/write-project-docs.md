# write-project-docs (Skill)

[中文](../../zh/skills/write-project-docs.md) | [English](../../en/skills/write-project-docs.md) | [日本語](write-project-docs.md)

> NixKits スタイルで完全な多言語ドキュメントを生成 — 中英日+偽中国語四言語、簡潔、表駆動。

## 基本情報

| 項目 | 値 |
|------|-----|
| タイプ | Coding Agent Skill |
| パス | `skills/write-project-docs/SKILL.md` |

## 機能

- プロジェクトのメタデータを評価しモジュール情報を抽出
- 機能別にモジュールを分類（インフラ/サービス/プロキシ/スキル）
- `docs/{zh,en,ja}/` ディレクトリ構造を生成
- 分類 README を作成（言語切替付き）
- モジュールドキュメントを作成（基本情報表 + インストール + 参照）
- 統一テンプレートでスキルドキュメントを作成（基本情報 → 機能 → 使用）
- サブエージェントによるモジュールカテゴリ別の並列化に対応

## スキルドキュメント同期ルール

`SKILL.md` が変更された場合、対応する 3 言語のドキュメントを必ず更新。
staleness check で古いファイルを特定：

```bash
for lang in zh en ja; do
  for skill in skills/*/SKILL.md; do
    name=$(basename $(dirname $skill))
    doc="docs/$lang/skills/$name.md"
    [ "$skill" -nt "$doc" ] && echo "STALE: $lang/$name"
  done
done
```

更新順序：中国語ベースライン → 英語翻訳 → 日本語翻訳 → 偽中国語翻訳。
列名マッピング：`基本信息` → `Info` / `基本情報` / `基本情報`、`功能` → `Features` / `機能` / `機能`。

- ゼロ修辞、表優先、コードブロックはコピペで実行可能
- 技術用語は英語のまま、警告は引用ブロック形式
- 中国語セクションタイトルは 2 または 4 文字で視覚的リズムを統一
- 目標行数 ~40-60 行。パッチ/モジュールドキュメントは 4 セクション標準（基本情報 → 修正内容 → インストール → 注意）
- 独立した技術詳細・トラブルシューティング・参考セクションは禁止 — `## 注意` の bullet に圧縮
- 4 つの README は必ず同時に更新
- ルートディレクトリには中国語（サフィックスなし）のみ配置、ローカライズ版（`*.en.md`、`*.ja.md`）は `docs/` に格納
- 全言語で基本情報セクションが必須（中文 `## 基本信息`、英文 `## Info`、日文 `## 基本情報`、偽中国語 `## 基本情報`）
- パッチ/モジュールのソース変更後は「修正内容」/「機能」リストを必ず同期、各 bullet は実際の変更に対応させる

## 使用

ユーザーが「ドキュメントを作成」または「NixKits スタイルでドキュメントを生成」と依頼したときに起動。
