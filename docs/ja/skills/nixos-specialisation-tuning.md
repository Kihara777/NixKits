# nixos-specialisation-tuning (Skill)

[中文](../../zh/skills/nixos-specialisation-tuning.md) | [English](../../en/skills/nixos-specialisation-tuning.md) | 日本語  | [偽中国語](../../pcn/skills/nixos-specialisation-tuning.md)

> NixOS の specialisation 面を設計し、ユニファイドメモリ（UMA）デバイスで llama.cpp のローカル推論を最適化します。

## 基本情報

| 項目 | 値 |
|------|-----|
| 種別 | Coding Agent Skill |
| パス | `skills/nixos-specialisation-tuning/SKILL.md` |

## 機能

- **面アーキテクチャ**：三ファイル構成（既定面 / 任意面 / 共有基盤）と上書き衝突の規則
- **帰属原則**：設定項目はそれを消費するモジュールに置き、面をまたぐ副作用を避ける
- **llama.cpp 最適化**：UMA デバイスでのパラメータ早見表と禁止項目
- **診断順序**：出力退化時は環境変数を先に除外し、その後に量子化とテンプレートを疑う
- **コンテキスト費用分析**：エージェントのツール schema が毎ターン生む固定費を検出
- **静黙故障の診断**：「サービスは active だが機能しない」問題の認識
- **実験有効性の自己点検**：無効な対照実験の認識

## 使い方

AI アシスタントが以下の状況で有効化します：

| 状況 | 契機 |
|------|------|
| 設定分割 | 「既定は最小 + 任意で全部入り」の二つの起動設定が必要 |
| 推論異常 | llama.cpp の出力退化、読み込み失敗、速度異常 |
| 最適化判断 | 単一の効果数値ではなく、費用・便益・代価の評価が必要 |
| 難診断 | サービスは正常に動作しているが機能しない |

## 中核原則

| 原則 | 説明 |
|------|------|
| リスト属性に `mkForce` を使わない | 他モジュールの寄与を削除する；`systemPackages` は追記する |
| 設定は消費者に帰属させる | あるサービスを使わない面がその副作用を受けるべきではない |
| 実測してから効果を主張する | 未実測の数値を助言に書かない |
| systemd 状態だけでなく設定ログを読む | 未読込モジュールの設定キーは静黙で無視される |
| 実験と本番が矛盾したら実験を疑う | 本番環境ではなく |
